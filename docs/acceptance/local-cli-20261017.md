## 已验证的行为

`shipbraid run --config PATH` 直接使用既有 Service/Engine/Store，不监听 HTTP、不读取客户端 token 文件、不启动后台协调器。配置的监听端口被占用时，包内 binary 仍能完成本地合成部署并取得匹配回执。多项目、并发调用者、后台持续观察和 Dashboard 使用 `serve`。

旧配置省略 `mode` 仍按 server 处理。Local 配置只允许同一个项目的 lanes，不接受 API tokens 或 Dashboard；`run` 拒绝 server 配置，`serve` 拒绝 local 配置且不打开账本。Local 拒绝其他项目或非 `local-cli` 主体的请求历史；两个进程不能同时持有同一个账本。

同 key/意图重放和 `--resume` 保留原请求，不重复 dispatch；不同意图冲突。零期限只返回快照，不 dispatch。非零期限与 SIGTERM 等待已经开始的 hook 交接收尾，停止后不撤回请求、不声称物理执行已停止，也不留下后台观察者。后续仍按原 request id 恢复。

Unknown 保留所有权，拒绝显式 retry；即使待重试请求指向旧失败执行，同一 lane 另有 Unknown 执行也不能重试。已证明失败的请求只有显式 `--resume ID --retry` 才会再次执行，保留请求身份。历史已终结请求返回自身结果，不受 lane 上其他 Unknown 执行影响。成功报告要求匹配回执；配置、hook 输出和凭据 canary 不进入报告或错误。

安装器默认 local，不生成 API token、`tokens.env` 或协调器 unit；显式 `--mode server` 保留原共享服务安装流程。现有 prefix 不会被覆盖。CLI 需要 Git；随附的真实项目 adapter 仍依赖 Python/systemd，文档明确了这些边界。

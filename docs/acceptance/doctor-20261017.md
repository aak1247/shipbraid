## 已验证的行为

`shipbraid doctor --config PATH` 默认输出文本，`--json` 输出 schema 1 报告。退出码为 0（无失败，允许 warning/skipped）、1（检查失败）、2（CLI 使用错误）。入口先于客户端凭据文件读取、HTTP client 和服务启动，因此无需在线协调器。

配置复用原解析、路径解析和静态校验；解析失败只报告固定建议，语义失败后继续安全的凭据/路径检查。报告只输出配置索引字段与固定文案，配置、环境引用、凭据值、hook 参数、路径及 parser/Git 原始错误的 canary 均未泄露。

黑箱夹具证明配置的 script、interpreter、command 和 PATH 中伪造的 Git/systemctl 没有执行；继承的 Git overrides 不影响探测。配置及 mirror 内容不变；缺失的数据库父目录仍不存在，已有非 SQLite 文件保持原字节且没有 WAL/SHM/journal/lock。源码入口不调用 Service/Store，也不读取配置中的数据库路径内容。

Git 探测只使用固定系统 Git，清理继承环境，禁用 hooks/fsmonitor/credentials/transports/lazy fetch/replace/可选锁；单次限制 2 秒与 4 KiB stdout。partial clone 检测读取 included config；完整性无法确认时跳过 ref 解析。输出过量、超时、直接和 include 中的 promisor 设置均有回归验证。

默认 runtime 项为 skipped。发行包验收显式检查本机 Unix user bus 与 cgroup v2，允许响应正常但 degraded 的 manager 作为 warning。诊断本身没有启停 unit。后续包级部署、重启和验收只操作临时合成任务。
